### [Nvidia 宣布 Rust 原生 CUDA 编程](https://developer.nvidia.com/blog/introducing-cuda-rust-two-tracks-for-writing-gpu-kernels/) ⭐️ 8.0/10

Nvidia 宣布为 CUDA GPU 内核提供原生 Rust 编程支持，并推出两条编写 GPU 内核的路径。这是 Rust 在高性能 GPU 计算领域的重要进展，为开发者提供了更安全的内核编写方式，同时解决了 Rust 与 CUDA 长期存在的绑定摩擦。该公告虽为渐进式演进而非范式转变，但内容实质且及时，已引发社区对技术影响与取舍的积极讨论。具体的技术细节、版本和性能数据尚未在公告摘要中披露，有待后续资料补充。

hackernews · nonmaskable · 9月16日 11:15 · [社区讨论](https://news.ycombinator.com/item?id=49724881)

**「背景」** 在 CUDA Rust 出现之前，在 Rust 中编写 GPU 内核通常需要借助绑定或包装层来调用其他语言的代码，而非直接进行原生编译。CUDA Rust 允许开发者直接用 Rust 编写 GPU 内核并将其原生编译为 PTX 指令集，同时提供与 CUDA 本身相同的两条轨道（tracks）。这一进展也建立在 Rust 工具链的持续演进之上，例如 2026 年 5 月发布的 Rust 1.97 已将 NVIDIA GPU 目标的支持提升至 PTX ISA 7.0 与 SM 7.0。

**「影响」** 该公告为 Rust 开发者开辟了编写原生 CUDA 内核的官方路径，改变了此前 Rust 需依赖第三方绑定或外部 DSL 的现状，显著降低了 Rust 进入高性能 GPU 计算的门槛。根据工具结果，旨在将 Rust 编译为快速 PTX 并复用 CUDA 库的 Rust CUDA 项目（rust-cuda）目前正在重启，NVIDIA 的官方支持将加速其成为 CUDA 一级语言的目标，并可能推动 AMD 等厂商在 GPU 编译器与运行时上加大 Rust 投入。

**「社区讨论」** 社区反馈呈现分歧：部分评论者看好该进展，认为与 Nvidia 旗下 Hugging Face 的 Candle crate 结合可推动原生 Rust 内核发展；另一些则批评 CUDA 的专有性，偏好 Metal、OpenCL 等开放标准或 Triton 类 DSL。此外，有评论因 LLM 尚未覆盖这些新内容而重燃学习 Rust 的兴趣。
