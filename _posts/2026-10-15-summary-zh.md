### [Cloudflare Workers 支持入站 TCP，gRPC 首个基于此构建](https://www.infoq.cn/article/f4DRCDXjQuOjpK4TXt6K) ⭐️ 8.0/10

Cloudflare Workers 现在可以接受入站 TCP 连接，不再只能作为 HTTP 服务器：新的连接（套接字）处理程序能接收原始入站套接字，经 Spectrum 路由到 Worker，Worker 可直接读写该套接字、转交其他 Worker 或交给 Durable Object，再通过 getTcpPort\(\) 传入 Container 完成全双工通信。gRPC 是首个构建在这一原语之上的协议——Workers 无需 Container 即可提供一元和服务器流式 gRPC 服务，也能调用外部 gRPC 服务器，但不支持双向流式传输，其底层是 gRPC 与 gRPC-web 之间的协议转换而非原生实现。Cloudflare 表示该功能目前处于私有测试阶段、需通过注册表单申请，并坦言公司内部使用的是 Cap&\#x27;n Proto、Cap&\#x27;n Web 和 Workers 内置的 JavaScript RPC 而非 gRPC，因此要先与一小部分 gRPC 开发者合作验证实现；官方社交媒体文案却称 gRPC 支持“现已可用”并在边缘原生提供、无需翻译层，与实际发布范围不符。Cloudflare 称下一步将支持基于 UDP 的协议。

rss · InfoQ 推荐 · 10月14日 07:41

**「背景」** Cloudflare Workers 自 2017 年推出以来，虽然可以打开通往数据库或服务的出站套接字，但作为服务器只能接收 HTTP 请求，入站 TCP 一直不被支持。gRPC 的流式传输、取消操作、流量控制和尾部元数据都依赖 HTTP/2 的流级控制，而 Web 平台 API（例如 fetch\(\)）并未暴露这种能力，这正是浏览器端出现 gRPC-web 的原因。Cloudflare 自 2020 年以来一直在其反向代理内部将 gRPC 转换为 HTTP/1.1，以便 WAF 规则和机器人管理能够检查消息内容。

**「实际影响」** 对计划采用的团队来说，最直接的约束是可用性与能力边界：连接处理器、gRPC 支持等功能目前都要通过注册表单进入私有测试，尚未全面可用，Cloudflare 也明说内部不使用 gRPC，因此不宜按 GA 排期。即便获得访问权，部署在 Workers 上的 gRPC 只支持一元和服务器流式调用，双向流式必须走 Worker→Durable Object→Container 这条路径；而 Cloudflare 官方社交渠道称 gRPC 支持“现已可用”，其范围比实际发布更窄。兼容性方面，现有 gRPC 客户端无需改动，服务端可用 @connectrpc/connect 编写几行代码接入，也可在既有 gRPC 后端前做前置层。

### [Anthropic 7 人 5 个月自研 Scion 替代 Git 支撑单体仓库](https://www.infoq.cn/article/6iRATYfkqF7aITPaFR2R) ⭐️ 8.0/10

Anthropic 在 10 月 13 日的官方工程博客中披露，其用一支 7 人团队、历经 5 个月开发出名为 Scion 的新版本控制系统，并完成了整个 Monorepo 的迁移，同时交付代码审查工具 Antique、代码搜索与权限管理等配套基础设施。推动这一改动的是代码合并量的暴涨：合并量从 5 月的日均约 2500 次升至 9 月的日均超 3 万次；其 Monorepo 主分支历史接近 100GB、压缩工作副本超 25GB，每天仅 CI 就需约 2500 万次代码检出，此前依赖 Git 浅克隆、稀疏检出、内部镜像和对象存储快照的方案已难以维持。Anthropic 报告迁移后 Scion 基础设施的 CPU 与内存占用降至原 Git 镜像方案的约 1/200，代码检出速度提升约两个数量级，CI 节省约 25% 的 CPU 容量；这些数字分属不同优化维度，并非所有操作都快 200 倍。Anthropic 同时强调，Scion 针对的是超大规模 Monorepo 的特殊场景，不适合作为通用 Git 替代品，现阶段也没有将其包装成对外产品的计划，公司更希望借此推动 Git 生态改进服务端扩展能力。

rss · InfoQ 推荐 · 10月14日 03:46

**「背景」** Git 的分布式设计要求每个客户端保存较完整的仓库历史，并具备独立完成提交、变基、历史查询等操作的能力；这对普通项目有效，但 Anthropic 的单体仓库主分支历史已接近 100GB、压缩工作副本超过 25GB，CI 每天约需 2500 万次检出。Anthropic 此前已用浅克隆、稀疏检出、内部镜像和对象存储快照等手段维持 Git，甚至维护数百台镜像服务器；随着 Claude 推动合并量从 5 月日均约 2500 次升至 9 月的 3 万次以上，这套方案越来越难支撑。

**「影响」** 对正在大规模引入 Coding Agent 的团队来说，这个案例说明瓶颈可能先从版本控制、CI 和合并队列暴露，而非代码生成本身：Scion 把提交、合并、变基和历史上传到服务端并通过 API 提供，使操作成本更多取决于实际改动量而非仓库规模。但 Anthropic 明确表示，Scion 依赖专门开发的代码审查、代码搜索和 CI 基础设施，普通团队迁移成本很可能远超收益，因此更现实的参考是服务端 API、稀疏检出与浅克隆、数据协商协议等方向上的 Git 生态改进。此外，Anthropic 披露其尚未找到在这一规模下复现全局仓库锁式合并队列的方法，转而加大合并后测试和部署前自动化测试投入，这意味着部分冲突可能在合并后才被发现，而该流程的缺陷率、回滚率与生产事故数据尚未公开，其质量与可靠性是否优于传统流程仍无法确定。

### [Ledger 证实 CryptoBilis 经销的硬件钱包被植入间谍芯片](https://www.solidot.org/story?sid=85604) ⭐️ 8.0/10

Ledger 证实，由马来西亚零售商 CryptoBilis 经销的部分硬件钱包被植入间谍芯片，导致客户钱包中的加密货币被盗，公司已要求 CryptoBilis 停止销售硬件钱包。Tibane Labs 的安全研究人员分析这批被篡改的 Ledger X（售价仅为原型号的一半）后发现，原装电池被替换为体积更小的电池以腾出空间安装恶意电路，该电池同时为间谍芯片和 Ledger X 供电。恶意电路的核心是一颗基于 Arm Cortex-M4 架构、配备 128 KB 闪存、采用 UFQFPN32 封装的 ST STM32G431KBU6 芯片，位于电池和天线下方，旁边装有微型 eSIM，并借助屏蔽式 LTE 模块发送信号。研究人员还发现第二种篡改版本使用原装电池供电，间谍芯片被安装在 OLED 显示屏下方原本用于放置泡沫衬垫的空间内，通过 OCR 读取钱包屏幕上显示的字体，在受害者设置过程中窃取密钥。

rss · 奇客Solidot–传递最新科技情报 · 10月14日 06:12

**「背景」** 硬件钱包将私钥离线保存在设备内，其安全模型建立在一个前提上：设备从出厂到用户首次完成初始化、生成并抄录助记词之前没有被改动过——助记词在设备屏幕上显示，任何能读取该屏幕内容的一方即可完全控制钱包资产。因此这类产品的防护重点不只是芯片本身，还包括从制造、封装到交付的整条流通链条；一旦设备经第三方经销商转手，用户就无法再依赖厂商出厂状态作为保障。此次涉事设备正属于这种情况：它们由总部位于马来西亚、业务遍及东南亚的零售商 CryptoBilis 经销，其中部分被篡改的 Ledger X 售价仅为原型号的一半。

**「对用户的影响」** 对从 CryptoBilis 购买 Ledger X 的用户而言，后果是直接的：密钥可能在设备初始化阶段即被 OCR 窃取，因此相关助记词应按已泄露处理并尽快转移资产，仅更换设备并不能挽回已被盗的资金。Ledger 已要求 CryptoBilis 停止销售硬件钱包，但报道未提及召回、检测或退款安排。

据财新网报道，中央纪委国家监委网站 2026 年 10 月 13 日通报，十八届中央委员、重庆原市长黄奇帆在退休 8 年后官宣落马。报道称，他在约一个月前的 9 月 8 日还以重庆市政府原市长身份在厦门举行的第八届“丝路海运”国际合作论坛上发表主旨演讲，原定 10 月 26 日在宁波银行杭州分行一场论坛担任主讲嘉宾的活动则在社交媒体上传出“因故取消”；中共二十大以来重庆已有郑洪、熊雪、陆克华、段成刚、江敦涛、胡衡华、罗蔺及黄奇帆等八名高官被查。
