React 19.3 于 9 月 9 日发布到 npm，除稳定的 View Transitions 和 Fragment Refs 外，还加入了 react-dom 的 browser\(\) API，让组件正式声明不参与服务器端渲染。组件调用 use\(browser\(\)\) 后，服务端渲染会暂停该组件，并在 HTML 中保留最近 Suspense 边界的备用内容；在浏览器中该调用返回 undefined，组件在水合后正常渲染。该 API 必须由客户端组件调用并置于 Suspense 边界内，否则服务端渲染会失败；同时 React 增加了 onBrowserBailout 回调和可选 reason 参数，用于报告 SSR 被跳过的位置。需要注意的是，官方用户指南仍将 browser\(\) 标注为仅限 Canary 通道，因此生产环境使用前应先确认自己的发布通道。

rss · InfoQ 推荐 · 10月24日 05:00

**「背景」** SSR 场景下，读取 localStorage、window 或设备时区的组件无法在服务端产出有意义的 HTML，此前常见做法是在 effect 里切换 mounted 标志，或用 typeof window \!== &\#x27;undefined&\#x27; 控制渲染，两者都可能造成服务端与客户端首次渲染不一致的水合不匹配。框架层面已有类似能力，但都绑定各自的打包工具：Next.js 用 next/dynamic 的 ssr: false，Astro 用 client:only 指令。browser\(\) 把这一“逃生舱”收进 React 本身，使其可用于任意 SSR 配置。

**「影响」** 对使用 SSR 的团队来说，可以直接用 browser\(\) 替换 mounted 标志和 typeof window 判断，并借助 use\(\) 可置于条件之后的特性做条件性数据获取：loader 提供 initialData 时在服务端渲染，否则跳过该路径。升级只需按 React 19 升级指南把 react 和 react-dom 调到 19.3，但若把调用放在非客户端组件或 Suspense 边界之外，服务端渲染会直接失败，加上文档仍标注 Canary 限制，落地前需确认通道与边界写法。
