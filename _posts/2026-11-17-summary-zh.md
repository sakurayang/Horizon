Docker 宣布将采用 Apache-2.0 许可的 Sandbox Kit 规范捐赠给 CNCF，并将其升级至 v3；该规范把 AI 智能体、所用工具，以及它申请的主机、凭证和卷权限清单，一起打包成一个普通 OCI 镜像，使现有构建、拉取、扫描、签名和 FROM 引用流程都能直接处理。镜像清单中只包含 vnd.docker.sandbox.kit.descriptor 这一项声明，权限则以类型化、版本化的能力表示，例如 com.docker.sandbox/network-policy@2；在 GitHub CLI 示例中，该 Kit 允许访问 api.github.com，但会拒绝 DELETE /repos/\*\*，且拒绝规则优先于允许规则，凭证可由代理托管，沙箱内只保留哨兵值。Kit 只是申请权限，最终由主机运行时裁定；如果没有符合规范的运行时，这一注解就不起作用；如果某项必需申请无法满足，启动就会被拒绝。Docker Sandboxes 是首个符合规范的运行时。由于目前唯一符合规范的实现是 Docker Sandboxes，跨运行时的可移植性尚未得到验证；CNCF 也未说明该规范将进入哪个孵化项目或成熟度等级。

rss · InfoQ 推荐 · 11月16日 08:22

**「背景」** OCI 镜像是按内容寻址的标准构件，通常通过 manifest 描述其内容，并可用现有的仓库、扫描和签名工具处理。Docker 将此次捐赠类比为此前捐赠镜像格式和 runc、最终催生 OCI 的举措；但 Sandbox Kit 新增的类型化权限声明能否生效，仍取决于是否符合规范的运行时。

**「落地影响」** 对采用者而言，直接后果是：现有镜像仓库、扫描和签名工具无需改动就能处理 Kit，但权限是否真正生效完全取决于运行时；目前 Docker Sandboxes 是唯一符合规范的实现，因此在其他运行时上，清单中的权限声明不会被执行，跨运行时可移植性也尚未得到验证。团队在把 Kit 用于生产前，应确认目标运行时符合规范，并固定镜像摘要，从而同时锁定内容与所申请的权限。
